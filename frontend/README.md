# Plus Smart Home Tech — фронтенд

Интернет-магазин умного дома на React 18 + Vite. Интерфейс собран по макету
[Plus Smart Home Tech](https://www.figma.com/design/3wAvShPJVxJZVqMNPzM6sO/Plus-Smart-Home-Tech)
(бежево-коричневая палитра, шрифт Inter, десктоп 1440 px с адаптивом под планшет и мобильные).

## Стек

- React 18 (JavaScript, без TypeScript);
- react-router-dom 6 — маршрутизация;
- Vite 5 — dev-сервер и сборка;
- обычный CSS с переменными (`src/styles/*.css`), без UI-библиотек.

## Структура

```
frontend/
├── index.html
├── vite.config.js          # порт 5173 + прокси /api → localhost:8080
└── src/
    ├── main.jsx            # точка входа, роутер, провайдер корзины
    ├── App.jsx             # все маршруты
    ├── api/client.js       # запросы к gateway + fallback на локальные данные
    ├── context/CartContext.jsx
    ├── components/         # Header, Footer, карточки, модалка оформления, иконки
    ├── pages/              # Home, Catalog, Product, Cart, Scenarios, Delivery, Contacts, 404
    ├── data/               # catalog.js (товары/сценарии/отзывы), content.js (тексты)
    ├── styles/             # global.css, layout.css, pages.css
    └── utils/format.js     # цены, склонения, промо-номера заказов
```

## Быстрый старт

```bash
cd frontend
npm install
npm run dev
```

Откройте <http://localhost:5173>.

Сборка и просмотр production-версии:

```bash
npm run build     # результат в frontend/dist
npm run preview   # локальный сервер поверх dist
```

Требуется Node.js 18+ (проверено на Node 20).

## Запуск вместе с бэкендом

Фронтенд обращается к gateway по относительному пути `/api`, а Vite проксирует его на
`http://localhost:8080` и убирает префикс `/api`:

| Запрос фронтенда | Что получает gateway |
| --- | --- |
| `GET /api/shopping-store?productCategory=LIGHTING&page=0&size=100` | `/shopping-store?...` |
| `GET /api/shopping-store/{productId}` | `/shopping-store/{productId}` |
| `GET /api/shopping-cart?username=...` | `/shopping-cart?username=...` |
| `PUT /api/shopping-cart?username=...` | `/shopping-cart?username=...` |
| `POST /api/shopping-cart/booking?username=...` | `/shopping-cart/booking?...` |
| `PUT /api/order` | `/order` |

### Порядок запуска бэкенда

Порядок важен: сервисы берут настройки из `config-server` через Eureka, а gateway и
`order` ходят друг к другу по именам сервисов. Запускайте строго по шагам и дожидайтесь
регистрации в Eureka (до 30 секунд), прежде чем идти дальше.

**0. Подготовка (один раз)**

- JDK 21 (проект собирается под `<java.version>21</java.version>`). Если в системе по
  умолчанию JDK 25, в IntelliJ: `File → Project Structure → Project SDK → 21`, там же
  `Build Tools → Maven → Runner → JRE → 21`. Иначе падает Lombok/аннотационная обработка.
- Docker Desktop запущен.
- Соберите общий модуль DTO (нужен для запуска сервисов из консоли; IDEA при запуске
  приложений компилирует модули сама):

```bash
# macOS: подставить JDK 21, если по умолчанию стоит другая версия
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
mvn -DskipTests -pl commerce/interaction-api -am install
```

**1. Базы данных и Kafka**

```bash
docker compose up -d
docker compose ps        # все контейнеры должны быть healthy/running
```

Postgres: store — 6432, cart — 7432, warehouse — 8432, delivery — 4432, payment — 3432,
order — 2432. Kafka (`9092`) нужна только телеметрии, для магазина не обязательна.

**2. Discovery Server** — `DiscoveryServerApplication` (`infra/discovery-server`)

- Порт 8761. Проверка: <http://localhost:8761> открывается Eureka Dashboard.

**3. Config Server** — `ConfigServerApplication` (`infra/config-server`)

- Порт случайный (`server.port: 0`), сервис регистрируется в Eureka.
- Проверка: в Eureka Dashboard в списке `CONFIG-SERVER`. Это обязательный шаг: у
  остальных сервисов `spring.config.import: configserver:` с `fail-fast: true`, без
  config-server они не стартуют (делают несколько retry и падают).

**4. Сервисы commerce — в порядке зависимостей**

| Шаг | Сервис | От кого зависит | Порт БД |
| --- | --- | --- | --- |
| 4.1 | `ShoppingStoreApplication` | — | 6432 |
| 4.2 | `WarehouseApplication` | shopping-store (обновление остатков) | 8432 |
| 4.3 | `ShoppingCartApplication` | warehouse (бронирование) | 7432 |
| 4.4 | `PaymentApplication` | shopping-store, order (колбэки) | 3432 |
| 4.5 | `DeliveryApplication` | order, warehouse | 4432 |
| 4.6 | `OrderApplication` | cart, warehouse, payment, delivery | 2432 |

Почему так: `order` при оформлении вызывает `cart → warehouse → payment → delivery`,
поэтому он запускается последним, когда остальные уже зарегистрированы. Порт у сервисов
случайный — ориентируйтесь на Eureka Dashboard.

**5. Gateway** — `GatewayApplication` (`infra/gateway`, порт 8080)

Проверка, что маршруты живы:

```bash
curl "http://localhost:8080/shopping-store?productCategory=LIGHTING&page=0&size=10"
# ожидается JSON-массив из 2 товаров (лампа L1 и L2 Color)
```

**6. Фронтенд**

```bash
cd frontend
npm run dev
```

По умолчанию Vite слушает <http://127.0.0.1:5173>. Если порт занят (например, другим
проектом), запустите на свободном: `npm run dev -- --port 5174`. Прокси `/api → :8080`
работает на любом порту.

Открыть <http://localhost:5173>: каталог должен показывать товары с сервера
(в backend `data.sql` — 8 позиций: 2 освещение, 3 датчика, 3 контроль).

### Быстрая проверка всей цепочки через API

```bash
# каталог
curl "http://localhost:8080/shopping-store?productCategory=SENSORS&page=0&size=10"

# корзина: положить товар
curl -X PUT "http://localhost:8080/shopping-cart?username=test-user" \
  -H "Content-Type: application/json" \
  -d '{"11111111-1111-1111-1111-111111111111": 2}'

# бронирование на складе
curl -X POST "http://localhost:8080/shopping-cart/booking?username=test-user"

# оформление заказа (нужны все шесть сервисов)
curl -X PUT "http://localhost:8080/order" \
  -H "Content-Type: application/json" \
  -d '{
        "shoppingCart": {
          "shoppingCartId": null,
          "products": {"11111111-1111-1111-1111-111111111111": 2}
        },
        "deliveryAddress": {
          "country": "Россия", "city": "Москва", "street": "Тверская",
          "house": "1", "flat": "10"
        }
      }'
```

Ответ `PUT /order` — объект заказа с `orderId`, `state: ON_PAYMENT`, рассчитанными
`productPrice`, `deliveryPrice`, `totalPrice`.

### Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| Сервис падает с `Could not resolve placeholder` / `Config server not found` | `config-server` ещё не зарегистрировался в Eureka — запустите его и подождите 20–30 с, затем перезапустите сервис |
| `Connect timed out` / `ConfigClientFailFastException`, в логе URL вида `http://192.168.x.x:<port>/<service>/default` | сменилась сеть (Wi-Fi/хотспот), а в Eureka остался старый `ipAddr` config-server. Перезапустите Config Server — он зарегистрируется с текущим IP. Быстрый обход: запустить сервис с `--spring.cloud.config.discovery.enabled=false --spring.cloud.config.uri=http://localhost:<порт>` |
| `ConfigClientFailFastException: Could not locate PropertySource`, в стеке `500` на `/<service>/default` | `config-server` жив, но не может разобрать конфиг сервиса — обычно синтаксическая ошибка YAML в `infra/config-server/src/main/resources/config/commerce/<service>/application.yaml`. Проверьте `ruby -ryaml -e 'YAML.load_file("...")'`, исправьте и повторите запрос (config-server перечитывает файл на каждый запрос) |
| Gateway отдаёт 503 `Unable to find instance` | нужный сервис не поднят или ещё не появился в Eureka; проверьте Dashboard и подождите ~30 с |
| `relation "products" does not exist` | не поднята соответствующая БД или сервис стартовал раньше Postgres; `docker compose ps`, затем перезапуск сервиса |
| `duplicate key value` при повторном старте shopping-store | в БД уже есть товары; в `data.sql` стоит `on conflict do nothing`, но если схему меняли — `docker compose down -v && docker compose up -d` |
| Ошибка компиляции Lombok на JDK 25 | переключите SDK и Maven Runner на JDK 21 |
| Порт 8080/8761/5173 занят | освободите порт: `lsof -ti :8080 \| xargs kill` |

Если бэкенд не запущен, интерфейс продолжает работать: каталог, товары, корзина и
оформление заказа переходят в демо-режим на локальных данных (см. ниже).

### Адрес API без прокси

Если фронтенд открыт не через Vite (например, `npm run preview` или собранная статика на
другом хосте), укажите полный адрес gateway при сборке:

```bash
VITE_API_BASE=http://localhost:8080/api/v1 npm run build
```

Переменная читается в `src/api/client.js`; по умолчанию используется `/api`.

## Демо-режим и локальные данные

- `src/data/catalog.js` — 10 товаров, 4 сценария, отзывы, категории, преимущества.
  Используется как мгновенный первый рендер и как fallback, если gateway недоступен.
  В бэкенде (`data.sql`) товаров 8 — «Датчик протечки W1» и «Умный выключатель S2» есть
  только в демо-каталоге, поэтому с включённым бэкендом в каталоге будет 8 позиций
  (2 освещение, 3 датчика, 3 контроль), а без него — 10.
- В `ProductDto` бэкенда нет полей `oldPrice`, `reviewCount`, `isNew`, поэтому они
  подмешиваются из локального каталога по `productId` (актуальные цена, название и
  описание при этом берутся с сервера).
- Корзина хранится в `localStorage` (`plus.cart.v1`) вместе со снимками товаров, поэтому
  переживает перезагрузку страницы.
- Имя пользователя для API генерируется один раз и хранится в `plus.username.v1`
  (`guest-xxxxxxxx`).
- Оформление заказа: сначала `PUT /shopping-cart` → `POST /shopping-cart/booking` →
  `PUT /order`. Если хоть один запрос не прошёл, показывается успешный демо-заказ с
  номером `PSH-XXXXXX` и пометкой, что бэкенд недоступен.
- Промокод корзины: `PLUS10` (−10 %). Доставка бесплатна от 5 000 ₽, иначе 490 ₽.

## Проверка запросов к API

1. Запустите бэкенд и фронтенд, откройте DevTools → Network.
2. Перейдите в каталог: должны уйти три запроса `GET /api/shopping-store?productCategory=…`.
   Код ответа 200 — данные пришли с сервера; если все три упали, каталог покажет локальные
   товары (в консоли будет `HTTP …`).
3. Оформите заказ: `DELETE /api/shopping-cart`, `PUT /api/shopping-cart`,
   `POST /api/shopping-cart/booking`, `PUT /api/order`.
4. Без запущенного gateway те же запросы завершатся ошибкой, а модалка покажет
   демо-заказ — это ожидаемое поведение.

## Известные ограничения

- Нет авторизации: используется сгенерированный `guest-…` пользователь.
- Заказы не отображаются в личном кабинете (его нет в макете).
- Отзывы и подписка не отправляются на бэкенд — API для них не предусмотрен.
- Изображения товаров берутся из `src/assets/images`; `imageSrc` с сервера сопоставляется
  с локальным файлом, иначе показывается картинка по категории.
